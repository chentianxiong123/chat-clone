# 2026-10-25 dsh-qqbot 插件研究与拟人仿造清单

## ① 目标与动机

我的 QQ 拟人 agent（`agent/`，个人号 NapCat → node-napcat-ts → 自写薄服务）想更**逼真拟人**，并且**全部配置驱动**（不写死路径），以后还要配一个 **web 控制台**。

腾讯官方出了 deepseek-harness（dsh）的 QQ 接入插件 `tencent-connect/dsh-qqbot`（MIT 开源），专门研究它有哪些拟人包装 + 并发/风控功夫值得抄进我这个不依赖 dsh 宿主的薄服务。

## ② 资源拓扑（探索对象长什么样）

├── model/          model-resolver + prefs-store（per-peer 覆盖持久化）
├── features/       question-channel（ask_user_question→内联按钮）

├── media/          vision-tool（读图）、send-file-tool（路径白名单）、media-cleaner（TTL）

└── middleware/     question-answer、attachment

## ⑤ 踩坑记录

1. **git clone 直连 GitHub 报 `Error in the HTTP2 framing layer`**
   → 根因：到 github.com 的 HTTP/2 流在代理/网络下不稳。
   → 解法：加 `-c http.version=HTTP/1.1` + 走 gh-proxy.com 前缀。
2. **克隆失败留半截目录**
   → 根因：协议失败在写盘中途发生。
   → 解法：`rm -rf` 目标目录再从头来，别在残目录上续。
3. **目录改名后 agent 的 RAG 路径悄悄失效**
   → 根因：`config.ts` 里默认值硬编码了 `/mnt/shared/qwen-chat/...sqlite`，仓库目录改名成 chat-clone 后必炸。
   → 解法：删掉默认路径，`RAG_DB_PATH` 走 env，没配就是关闭 RAG。已改。
4. **RAG 名不副实**（现状不是 bug 是决策）
   → 现象：README 写的是向量检索 sqlite-vec，但 `agent/rag.ts` 实际是 bigram 关键词 `LIKE` 搜索。
   → 决策：先用 LIKE（免费、不依赖 embedding 服务），向量化留作待定（见⑧）。

## ⑦ 决策记录

| 决策 | 为什么不选另一条 |
|---|---|
| agent 用自写薄服务 + OneBot SDK，**不用 AstrBot 当大脑** | 我要 100% 把控 agent 逻辑 + 自己的知识库；AstrBot 是挺重的 Python web 框架，会把我圈在它的插件模型里 |
| 协议端用 **NapCat** | 维护最活跃（2026-10 还在发版）、真客户端登录不靠公共 sign server（Lagrange 系的最大坑）；用重一点的 RAM 换稳 |
| **不搬** dsh 的 session fork / compaction / agent-presets / 扫码绑定 | 全部绑死 deepseek-harness 宿主服务，薄服务里没有这些 service 可调 |
| **不搬** reply-limiter/msg-id 降级 | 那是腾讯官方 BOT 的被动回复配额规则，个人号 NapCat 机制不同（我已有 REPLY_COOLDOWN 防风控） |
| transport->inbound 的 5 层消息组装**要搬到 prompt 侧实现** | 它解决的都是“LLM 怎么知道谁在说、在回哪句话、群里刚才聊到哪”的拟人上下文问题，跟协议无关 |
| `conf.ts` 配置**照抄 schema 化思路**（类型+默认值+中文说明） | 为将来的 web 控制台铺路——一个 schema 驱动面板读写 |

## ⑧ 未解之谜 / 下一步岔路

- **高价值三点改造**（优先做，直接上 `agent/index.ts`）：
  1. 群聊被 @（或攒批触发）时，把最近 N 条群聊记录按 `[聊天记录起]...` 包进上下文（抄 inbound Layer 5）
  2. 回复带引用：NapCat 消息里带 `.reply` 指向对方那条消息（抄 reply-target）
  3. 长回复按 markdown 感知切分 + 分批发送间隔（抄 chunker）
- **web 控制台**：参考 dsh 的 `client/`（端内绑定页+配置面板）+ `config.ts` schema 一文结构；AstrBot 的 dashboard 也可以翻翻。
- NapCat 个人号**内联按钮支持程度未知** → 问答降级方案：发编号列表让用户回数字（抄 question-channel 的多选语义）。
- RAG 是否换**真向量检索**：本地有 qwen3-embedding-0.6b（llama/ 路径已准备），可做 sqlite-vec 向量查询，跟 README 对齐。
- 语音/图片进上下文：NapCat 个人号图片给 URL、语音给文件，本地 LLM 若没视觉/ASR 就只是占位描述，价值待测。
