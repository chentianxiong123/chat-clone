# chat-clone 大重构：彻底改用 pi-agent-core 内核

> 日期：2026-11-07
> 状态：进行中（P0 起步）
> 决策：彻底改动——v2 定为唯一规范 agent，v1 core.ts 删除，全面改用 pi `AgentMessage`，接 API 走自定义 pi-ai Model（路线 B），SQLite 存储退纯归档，RAG 知识库不动。

## 一、目标

把 chat-clone 手搓的 LLM+工具循环（`llm.ts callLlmWithTools`）+ DB 上下文（`memory.ts loadDialog/saveDialog`）换成 pi 内核：

- **live 上下文 = `Agent.state.messages[]`**（内存数组，pi 管）
- **LLM+工具循环 = `@earendil-works/pi-agent-core` 的 `Agent`**（自带 loop + 工具执行 + 流式）
- **上下文裁剪 = `Agent.transformContext`**
- **清空 = `Agent.reset()`**（保留 system baseline）
- **存储 = SQLite 纯归档，永不回灌上下文**
- **知识库 = RAG（qwen_persona_rag.sqlite）独立不动**

## 二、决策（已定）

| 项 | 选择 |
|---|---|
| 规范 agent | **v2**（kernel/harness/runtime/store），v1 core.ts 删 |
| 消息契约 | 全面改用 pi `AgentMessage`（`convertToLlm` 在适配层） |
| 接 API | 路线 B：自定义 pi-ai Model（`openAICompletionsApi`，复用 pi 流式） |
| 存储 | SQLite 归档（scene_dialog / agent.db），上下文不再 loadDialog 回灌 |
| 知识库 | RAG 独立，`search_past_memory` 继续查 |

## 三、pi 包依赖（`@earendil-works/*`）

只装要用的，不拖全套：

- **`@earendil-works/pi-agent-core`** — `Agent`（LLM loop、工具执行、流式、transformContext/reset）
- **`@earendil-works/pi-ai`** — `createProvider`/`createModels`/`envApiKeyAuth`/`openAICompletionsApi`（agent-core 的依赖，自动带上）
- 不用：`pi-durable`（Experimental）、`pi-mcp`、`pi-coding-agent`、`pi-tui`、`chord`

## 四、「真发群聊被包装成 reply 工具」在 pi 的落地

现有链路（v2/runtime.ts:186-198）：`reply` 工具攒 `sentTexts` → 或 assistant 文本 `raw` → `sendSegments` → `this.send(thread,...)` 真发。

pi 里同构保留，驱动者换成 pi Agent：

```
pi Agent（模型自主想/搜/决定）
   ├─ 调 reply 工具 → AgentTool.execute 攒 collector（sentByTool=true）
   ├─ 或直接出 assistant 文本 → subscribe message_update 攒 text_delta
   └─ 都没调 = 沉默
        ↓
collector 文本 或 assistant 文本 → sendSegments → this.send（真发）
```

- `reply` = `AgentTool {name, description, parameters, label, execute}`，`execute` 里 `params.messages` 进 collector，返回 `AgentToolResult {content:[{type:'text',text:'ok'}], isError:false}`
- assistant 文本靠 `agent.subscribe` 的 `message_update`（`assistantMessageEvent.type==='text_delta'`）攒，`turn_end` 收尾
- 沉默：collector 空 且 assistant 无文本 → 不发

## 五、接 API：自定义 pi-ai Model（路线 B）

`agnes-2.5-flash` 走 OpenAI 兼容端点（`LLM_BASE_URL`）。pi-ai 的 `openai-completions` API 用 `model.baseUrl`，所以自定义 provider 指到本地端点即可：

```ts
// pi-provider.ts（新建）
import { createProvider, createModels, envApiKeyAuth } from "@earendil-works/pi-ai/models"
import { openAICompletionsApi } from "@earendil-works/pi-ai/providers/openai-completions.lazy"

const provider = createProvider({
  id: "local", name: "本地 agnes", baseUrl: config.llm.baseUrl,
  auth: envApiKeyAuth("LLM_API_KEY", ["LLM_API_KEY"]),
  models: [{
    id: config.llm.model, name: "agnes-2.5-flash", api: "openai-completions",
    provider: "local", baseUrl: config.llm.baseUrl, input: ["text"],
    cost: { input:..., output:... }, reasoning: false,
    contextWindow: ..., maxTokens: ...,
  }],
  api: openAICompletionsApi(),
})
const models = createModels()
models.setProvider(provider)
export const streamFn = models.streamSimple.bind(models)
```

- `Tool` 基类型（pi-ai types.ts:779）：`{name, description, parameters}`，parameters 是 JSON Schema —— chat-clone `ToolSpec.function` 直接转
- `AgentTool`（agent-core）：加 `label` + `execute(toolCallId, params, signal, onUpdate) => Promise<AgentToolResult>`
- `AgentToolResult.content` 是 `TextContent[]`（`[{type:'text',text}]`）

- `AgentMessage`（含 toolCall/structured 块）适配层
- `streamFn`/Model 必填字段（`input`/`cost`/`contextWindow`/`maxTokens`）构造
- `AgentToolResult.content` 是 `TextContent[]`，`reply` 返回适配
- `message_update` 事件流式攒文本格式
- 删 v1 前确保 webui/index 全切 v2，避免半吊子
